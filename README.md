# Master VPN — Telegram-бот на Partner API «Мастерская VPN»

Бот продаёт доступ к VPN (Stars, USDT; рубли по СБП через platega.io) и выдаёт ссылку-подписку
через Partner API. Экраны сделаны по PDF с UX: один экран = одно сообщение, навигация со стеком, «Назад» всегда на
один уровень назад. Язык один — русский (тексты в `app/texts.py`).

## Быстрый старт (VPS + docker compose)

1. Домен с A-записью на VPS. Откройте порты 80 и 443.
2. `cp .env.example .env` и заполните: `BOT_TOKEN`, `ADMIN_IDS`, `PARTNER_API_KEY`, `DOMAIN`, `PUBLIC_BASE_URL`,
   `POSTGRES_PASSWORD`, ссылки, **все 36 цен** `PRICE_*` (примеры в файле — замените своими).
   Без полной матрицы цен бот не стартует и назовёт недостающие переменные.
3. `docker compose up -d --build` — применит миграции, бренд (`PATCH /branding`) и запустит бота.
4. Вебхук Partner API (один раз):
   ```bash
   docker compose run --rm bot python -m app.scripts.set_webhook   # напечатает PARTNER_WEBHOOK_SECRET=...
   # впишите секрет в .env, затем:
   docker compose up -d bot
   docker compose run --rm bot python -m app.scripts.set_webhook --test
   ```
   Каждый запуск `set_webhook` выпускает **новый** секрет, прежний перестаёт подходить.
5. CryptoPay: в @CryptoBot → Crypto Pay → создайте приложение, токен — в `CRYPTOPAY_TOKEN`,
   Webhook URL приложения — `https://<домен>/cryptopay-webhook`.

При старте бот шлёт админам предупреждения: тестовый ключ, пробный проект, незаполненные ссылки (`CHANGE_ME`),
рублёвая цена ниже себестоимости, нет секрета вебхука или токена CryptoPay.

## Порядок запуска

1. **Пробный проект** (первый проект в кабинете): бесплатно, 3 клиента, 14 дней, продаётся только «Тест интеграции»
   на 2 устройства (бот сам ограничит срок 14 сутками). Продления и триал для клиентов недоступны — это нормально.
2. **Боевые условия**: пополните Кошелёк в кабинете на 1 000 ₽ и больше. После этого перезапустите бота — он
   подтянет ступени сетки (1/2/4/8 устройств). Бот проверяет `mode` в `GET /me` и предупреждает о тестовом ключе.
3. Следите за Кошельком: когда денег не хватает, оплаченные заказы ждут в очереди и выдаются сами после пополнения
   (`balance.low` и «Кошелёк пуст» приходят админам).

## Как это работает

- **Заказ** = `PUT /users/tg-<id>` (покупка) или `POST /users/tg-<id>/extend` (продление), `Idempotency-Key` =
  `"{провайдер}-{ID платежа}"`, потолок `max_charge_minor` берётся из свежего `/quotes`. Повторное уведомление об
  оплате заказа не создаёт.
- **Статусы платежа**: `created → paid → fulfilling → fulfilled | failed → refunded`, `created → expired`.
  Переходы атомарные; выдача, зависшая после падения, возвращается в очередь через 5 минут.
- **Временные ошибки** (сеть, 429, 5xx, `insufficient_balance`, `economics_not_ready`, `price_changed`) — автоповтор раз
  в минуту тем же ключом. **Окончательные** — клиенту наш текст, админу код, `request_id` и кнопки
  «Повторить» / «Возврат Stars».
- **Кто что видит**: активная платная подписка — только «Продлить»; истекла — «Продлить» и «Купить» (любое число
  устройств; если подключено больше устройств, чем в тарифе — бот предупредит до оплаты); после триала — только
  «Купить» (у действующего триала число устройств менять нельзя).
- **Stars**: в `pre_checkout` проверяются `orders_enabled` и баланс Кошелька (при недоступности API оплату не блокируем).
- **USDT**: счёт 60 минут, вебхук + кнопка «Проверить оплату». **Рубли**: заглушка «скоро будет доступно».
- **Уведомления клиенту**: срок закончился, трафик закончился, напоминание за 3 дня (раз на срок). Админу:
  оплата выдана, ошибка выдачи, Кошелёк пуст, `balance.low`.
- **Админ** (`ADMIN_IDS`): `/user <tg_id>` (пауза / возобновить / новая ссылка), `/stats`, `/pending`; действия пишутся в
  таблицу `admin_audit`.
- **Антифлуд**: 1 действие в секунду на пользователя, один открытый счёт на способ оплаты.
- Вебхуки: подпись по сырому телу, окно ±5 минут, дедупликация по `id`, незнакомый `type` получает 2xx.

## Подключение Platega (рубли, СБП)

1. В `.env`: `PLATEGA_MERCHANT_ID`, `PLATEGA_SECRET` (кабинет Platega → Настройки), `PLATEGA_ENABLED=true`.
2. В кабинете Platega → Настройки → Callback URLs: `https://<домен>/platega-callback`.
3. `docker compose up -d --build` и тестовый платёж.

Как работает: счёт создаётся `POST /transaction/process` (способ 2 – СБП QR, 15 минут). Доступ выдаётся только после
`CONFIRMED`, который бот перепроверяет запросом `GET /transaction/{id}` и сверкой суммы; колбэк без проверки не
считается оплатой. Потерянные колбэки добирает проверка открытых платежей раз в минуту. Возвраты, диспуты и
чарджбэки админам приходят уведомлением, автоматических действий нет. Если Platega не принимает `metadata`,
запрос повторяется без неё; другой адрес создания платежа – `PLATEGA_CREATE_PATH` (например `/v2/transaction/process`).

## Тесты и разработка

```bash
pip install -r requirements-dev.txt
python -m pytest            # 31 тест: конфиг, заказы и повторы, вебхуки, клиент API, экраны
```
Миграции: `alembic upgrade head` (`DATABASE_URL` из окружения). Бэкап БД:
`docker compose exec db pg_dump -U master master | gzip > backup-$(date +%F).sql.gz` (по cron раз в сутки).

## Структура

```
app/main.py            запуск: бот (polling) + aiohttp-сервер вебхуков + фоновые задачи
app/ui/nav.py          Navigator: стек экранов в БД, show() правит одно сообщение
app/ui/screens.py      все экраны по PDF
app/handlers/          user (callbacks, Stars), admin, антифлуд
app/services/          orders (выдача), payments (счета), plans (ступени), subscription (состояние клиента)
app/partner/client.py  клиент Partner API: повторы, идемпотентность, запасные адреса
app/providers/         cryptopay, platega
app/webhooks.py        /partner-webhook, /cryptopay-webhook, /platega-callback, /health
app/jobs.py            старт-проверки, очередь выдачи, напоминания, суточные задачи
migrations/            Alembic;  tests/ — pytest
```
